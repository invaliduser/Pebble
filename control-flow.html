Pebble Control Flow

Pebble is one atom plus two adapters. HTTP shows the atom in a browser; the socket accepts EDN commands that can read or change it.

The Whole Shape

-main reads ports, starts both servers, prints their addresses, and then waits forever. Both servers point at the same !state. 

flowchart TD
  Main["-main"]
  Env["env-int reads port env vars"]
  HttpStart["start-http!"]
  SockStart["start-socket!"]
  App["app"]
  SocketLoop["accept loop"]
  Client["serve-client"]
  Command["handle-line -> apply-command"]
  State["!state atom"]
  Browser["browser GET / or /state"]
  Netcat["socket client sends EDN lines"]

  Main --> Env
  Main --> HttpStart
  Main --> SockStart
  HttpStart --> App
  SockStart --> SocketLoop
  SocketLoop --> Client
  Browser --> App
  App --> State
  Netcat --> Client
  Client --> Command
  Command --> State

Socket Path

The socket path is line-oriented. Each line is read as EDN, interpreted as a command map, printed back as EDN, and followed by a newline. 

sequenceDiagram
  participant C as Socket client
  participant S as serve-client
  participant H as handle-line
  participant A as apply-command
  participant M as !state

  C->>S: "{:op :assoc :path [:plan 0] :value \"hello\"}\\n"
  S->>H: line string
  H->>A: EDN command map
  A->>M: swap! assoc-in
  M-->>A: updated map
  A-->>H: "hello"
  H-->>S: "hello"
  S-->>C: "\"hello\"\\n"

HTTP Path

HTTP is currently just a display adapter. The page fetches /state, and /state prints the current atom value with pr-str. 

sequenceDiagram
  participant B as Browser
  participant App as app
  participant Page as page.html
  participant M as !state

  B->>App: GET /
  App->>Page: slurp public/page.html
  Page-->>B: HTML + fetch script
  B->>App: GET /state
  App->>M: deref
  M-->>App: current map
  App-->>B: EDN string

Function Roles

Function Role
apply-command The little language: :ping, :state, :get, :assoc, :reset, :bye.
handle-line Turns one socket line into EDN, calls apply-command, and returns either the value or an error string.
serve-client Loops over lines from one client, writes one EDN result per line, and stops when the result is :bye.
start-socket! Creates the server socket and starts the accept loop.
app Routes HTTP requests for /, /state, and unknown paths.
-main Chooses ports, starts HTTP and socket servers, prints addresses, and keeps the process alive.
